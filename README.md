## 🔍 Описание проблемы и механизмы защиты

В релизной версии **Naruto: Naiteki Kensei** класс **ANBU** (`CAnbu` со своими техниками, мечом и дзюцу *Katon: Goukakyuu Anbu*) полностью реализован в коде сервера, но скрыт от обычных игроков. При попытке выбрать его через консоль сервер либо игнорировал команду, либо падал с фатальной ошибкой.

В ходе дизассемблирования `mp.dll` (PE32, `ImageBase = 0x10000000`) было выявлено **три уровня защиты**:
1. **Криптографический белый список (SHA-1):** проверка `SteamID` игрока по зашитым в бинарник SHA-1 хэшам разработчиков и тестеров мода.
2. **Порча строки класса в `.rdata`:** намеренная замена первых двух байт строки `"anbu"` на `"5\0"`, из-за чего сервер при спавне пытался загрузить несуществующую модель `models/player/5/5.mdl` и аварийно завершался.
3. **Зависимость от таблицы релокаций (`.reloc`):** наличие релоцируемого вызова WinAPI прямо внутри блока проверки прав, что приводило к повреждению машинного кода при загрузке DLL по динамическому базовому адресу (ASLR).

### 1. Проверка SteamID по SHA-1 хэшам (CryptoPP)

В обработчике консольных команд `ClientCommand` команда `selclass` (`VA: 0x10008AF3` / `Offset: 0x007EF3`) передаёт аргумент игрока в функцию смены класса **`0x1003BC10` (`Offset: 0x03B010`)**.

Функция поочерёдно сравнивает введённое имя класса через `_stricmp`:
* `"naruto"` (`0x100CC2A4`)
* `"sasuke"` (`0x100CC2AC`)
* `"sakura"` (`0x100CC2B4`)
* `"kakashi"` (`0x100CC2BC`)
* Пятый слот (`0x100CEC38`) — класс `CAnbu`.

Сразу после совпадения с пятым слотом (`Offset: 0x03B16B`) вызывается `g_engfuncs.pfnGetPlayerAuthId` для получения SteamID игрока, после чего строка передаётся в функцию **`0x1004D470` (`Offset: 0x04C870`)**:

```x86asm
0x1003BD6B: mov eax, [esi+4]              ; CBasePlayer->pev
0x1003BD6E: mov eax, [eax+208h]           ; edict_t*
0x1003BD74: push eax
0x1003BD75: call dword ptr [0x100F9F74]   ; pfnGetPlayerAuthId(edict)
0x1003BD7B: add esp, 4
0x1003BD7E: mov ecx, eax                  ; ECX = char* SteamID
0x1003BD80: call 0x1004D470               ; CheckDevSteamID_SHA1(SteamID)
0x1003BD85: test eax, eax                 ; Возвращает индекс (0..28) или -1
0x1003BD87: jl short 0x1003BDF9           ; Если < 0 — отказ в доступе!
```

Внутри `0x1004D470` используется встроенная библиотека **CryptoPP (`CryptoPP::SHA1` + `HexEncoder`)**, которая вычисляет SHA-1 хэш от SteamID игрока в верхнем регистре и сверяет его с таблицей из **29 зашитых хэшей** разработчиков в `.rdata` (начиная с `9035476E40E6FAF317C0AB3D8DBECF5CCA83E826`).

### 2. Обфускация имени класса в секции `.rdata` (ловушка краша)

После снятия проверки SteamID (`7C 70` -> `90 90`) сервер начинал создавать объект `CAnbu` (`new(0x10)` -> конструктор `CAnbu::CAnbu` по адресу `0x10060BD0` / `Offset: 0x05FFD0`), но **падал при спавне игрока**.

Анализ таблицы виртуальных методов `CAnbu::vftable` (`0x100D61C4`) выявил причину:
* Метод `CAnbu::GetClassName()` (`vftable[+18h]`, `VA: 0x10060B40`) возвращает указатель на константу **`0x100CEC38` (`Offset: 0x0CDE38`)**.
* Метод `CBasePlayerClass::SetPlayerModel()` (`vftable[+14h]`, `VA: 0x10060A20`) дважды вызывает `GetClassName()` и подставляет результат в форматную строку **`"models/player/%s/%s.mdl"`** (`0x100CEEA8`):

```x86asm
0x10060A3B: mov edx, [eax+18h]            ; vftable[+18h] -> GetClassName()
0x10060A3E: call edx                      ; Возвращает указатель 0x100CEC38
...
0x10060A4F: push 0x100CEEA8               ; "models/player/%s/%s.mdl"
0x10060A55: call sprintf                  ; Собирает путь к модели!
0x10060A64: call dword ptr [0x100F9D44]   ; pfnSetModel(edict, buffer)
```

В дампе секции `.rdata` по смещению `0x0CDE38` (`VA: 0x100CEC38`) были обнаружены байты:
```text
Offset 0x0CDE38: 35 00 62 75 00   -->   "5\0bu\0"
```
Разработчики перед компиляцией перезаписали первые два байта строки `"anbu\0"` (`61 6E 62 75 00`) на `"5\0"` (`35 00`). В результате `sprintf` формировал путь **`models/player/5/5.mdl`**, которого не существует в ресурсах игры (реальная модель лежит по пути `models/player/anbu/anbu.mdl`), что вызывало мгновенный краш движка Half-Life при вызове `pfnSetModel`.

Восстановление двух байт `35 00` -> `61 6E` (`"anbu"`) на `0x0CDE38` одновременно чинит:
* Загрузку корректной модели `models/player/anbu/anbu.mdl`.
* Все 18 проверок класса Анбу в логике способностей, чакры, анимаций (`idle_anbu`) и техник (`gouk_ball_anbu`).
* Нативную работу команды `selclass anbu`.

### 3. Учёт таблицы релокаций `.reloc` (ASLR)

При попытке расширить логику команды `selclass` (чтобы работали обе команды: и `selclass anbu`, и `selclass 5`) была учтена структура таблицы базовых релокаций (`.reloc`).

На смещении `0x03B175` находится инструкция `FF 15 74 9F 0F 10` (`call dword ptr [0x100F9F74]`), операнд которой (`0x03B177`) зарегистрирован в `.reloc`. Если перезаписать эти байты другим кодом, загрузчик Windows при релокации DLL прибавит дельту `ImageBase` поверх новых инструкций и повредит их.

Решение: инструкция `FF 15 74 9F 0F 10` оставлена на своём точном смещении, а проверка альтернативного аргумента `"5"` обходит её коротким прыжком `jmp short 0x03B189` (`EB 15`).

## 💻 Автоматический скрипт сборки патча (PowerShell)

Скрипт работает с **оригинальным немодифицированным** `mp.dll` из мода *Naruto: Naiteki Kensei*, проверяет целостность сигнатур перед записью и сохраняет готовый `mp_anbu_ready.dll`.

```powershell
# ==============================================================================
# Naruto: Naiteki Kensei — Anbu Class Unlocker (mp.dll Binary Patcher)
# ==============================================================================

$inFile  = ".\mp.dll"
$outFile = ".\mp_anbu_ready.dll"

if (-not (Test-Path $inFile)) {
    Write-Error "Файл mp.dll не найден! Поместите скрипт в папку с оригинальным mp.dll."
    exit 1
}

$bytes = [System.IO.File]::ReadAllBytes($inFile)

# 1. Проверка и восстановление строки "anbu" в секции .rdata (Offset: 0x0CDE38, VA: 0x100CEC38)
# В оригинале разработчики заменили первые 2 байта "anbu\0" на "5\0bu\0" (35 00 62 75 00)
$strOff = 0x0CDE38
if ($bytes[$strOff+2] -eq 0x62 -and $bytes[$strOff+3] -eq 0x75 -and $bytes[$strOff+4] -eq 0x00) {
    $bytes[$strOff]     = 0x61 # 'a'
    $bytes[$strOff + 1] = 0x6E # 'n'
    $bytes[$strOff + 2] = 0x62 # 'b'
    $bytes[$strOff + 3] = 0x75 # 'u'
    $bytes[$strOff + 4] = 0x00 # '\0'
    Write-Host "[OK] Патч 1: Строка класса на 0x0CDE38 восстановлена в 'anbu' (модель models/player/anbu/anbu.mdl)." -ForegroundColor Green
} else {
    Write-Error "Неожиданные байты на смещении 0x0CDE38! Возможно, это другая версия mp.dll."
    exit 1
}

# 2. Патч функции SHA-1 проверки SteamID разработчиков (Offset: 0x04C870, VA: 0x1004D470)
# Заменяем начало функции на xor eax, eax; ret (33 C0 C3)
$bytes[0x04C870] = 0x33
$bytes[0x04C871] = 0xC0
$bytes[0x04C872] = 0xC3
Write-Host "[OK] Патч 2: Функция SHA-1 проверки SteamID (0x04C870) пропатчена на возврат 0." -ForegroundColor Green

# 3. Патч обработчика selclass (Offset: 0x03B165 .. 0x03B188)
# Поддержка обеих команд ('selclass anbu' и 'selclass 5') с сохранением релокации на 0x03B177
$selclassOff = 0x03B165
if ($bytes[0x03B175] -eq 0xFF -and $bytes[0x03B176] -eq 0x15 -and $bytes[0x03B177] -eq 0x74) {
    $patchCode = [byte[]](
        0x74, 0x22,                         # 0x03B165: jz short 0x03B189 (если stricmp == "anbu" -> CAnbu)
        0x80, 0x3F, 0x35,                   # 0x03B167: cmp byte ptr [edi], '5'
        0x75, 0x16,                         # 0x03B16A: jnz short 0x03B182
        0x80, 0x7F, 0x01, 0x00,             # 0x03B16C: cmp byte ptr [edi+1], 0
        0x75, 0x10,                         # 0x03B170: jnz short 0x03B182
        0xEB, 0x15,                         # 0x03B172: jmp short 0x03B189 (если "5" -> CAnbu, обходя релокацию)
        0x90,                               # 0x03B174: nop
        0xFF, 0x15, 0x74, 0x9F, 0x0F, 0x10, # 0x03B175: оригинальный call [pfnGetPlayerAuthId] (релокация 0x03B177 сохранена)
        0x90, 0x90, 0x90, 0x90, 0x90, 0x90, # 0x03B17B..0x03B180: nop
        0x90,                               # 0x03B181: nop
        0x0F, 0x85, 0x71, 0x00, 0x00, 0x00, # 0x03B182: jnz 0x03B1F9 (штатный выход, если ни "anbu", ни "5")
        0x90                                # 0x03B188: nop -> далее 0x03B189 (создание объекта CAnbu)
    )
    [Array]::Copy($patchCode, 0, $bytes, $selclassOff, $patchCode.Length)
    Write-Host "[OK] Патч 3: В selclass (0x03B165) разблокированы 'selclass anbu' и 'selclass 5'." -ForegroundColor Green
} else {
    Write-Error "Сигнатура релокации на 0x03B175 не совпала! Проверьте исходный mp.dll."
    exit 1
}

[System.IO.File]::WriteAllBytes($outFile, $bytes)
Write-Host "`n[ГОТОВО] Пропатченная библиотека сохранена как: $outFile" -ForegroundColor Cyan
```

## 🚀 Установка и использование на сервере

1. Сделайте резервную копию оригинального файла `nnk/dlls/mp.dll`.
2. Запустите PowerShell-скрипт в папке с оригинальным `mp.dll`.
3. Переименуйте полученный `mp_anbu_ready.dll` в `mp.dll` и поместите в папку `nnk/dlls/` вашего сервера.
4. Зайдите на сервер, выберите команду (`chooseteam` / меню выбора команды) и введите в консоль игры любую из команд:
   ```text
   selclass anbu
   ```
   или
   ```text
   selclass 5
   ```
5. Игрок возродится в облике **ANBU** с его уникальным набором атак, мечом и техниками.

> **Примечание по VGUI-меню (`chooseclass`):** графическое окно выбора персонажа (`VGUIMenu` ID `51`) отрисовывается на стороне клиента в `cl_dlls/client.dll`, поэтому кнопка Anbu в нём отсутствует. Для удобного выбора на публичном сервере можно забиндить команду (`bind "F5" "selclass anbu"`) или добавить пункт в серверное AMX Mod X меню.
